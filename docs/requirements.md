# SmartLect — требования (v0.3)

> Статус: обсуждается. Пометка **[?]** — открытый вопрос, **[later]** — не входит в MVP.

## 1. Назначение

SmartLect записывает лекцию (аудио + фото доски с таймкодами) и автоматически
делает из неё конспект в Markdown с формулами в LaTeX.

## 2. Пользователи

- **Студент** — единственная роль в MVP.
- В будущем те же функции через другие клиенты: браузерное расширение,
  интеграция с приложениями для созвонов **[later]**. Поэтому API не привязан к
  конкретному клиенту, а у лекции хранится источник (`source`).
- Совместный доступ, курсы/предметы **[later]**.

## 3. Компоненты

| Компонент | Технологии | Роль |
|---|---|---|
| Клиент | Flutter **[later]** | запись аудио, фото, просмотр конспектов |
| Оркестратор | Scala 3, Spring Boot, PostgreSQL | API, авторизация, хранение метаданных, управление обработкой |
| Хранилище файлов | S3 (SeaweedFS локально) | аудио, фото, результаты |
| Очередь | RabbitMQ | задачи для воркеров и события от них |
| ML-воркер | Python | распознавание речи, распознавание доски, генерация конспекта |

## 4. Функциональные требования (MVP)

### 4.1 Аккаунт
- FR-1. Регистрация по email и паролю. Пароль хранится как BCrypt-хеш.
- FR-2. Вход: выдаётся access-токен (JWT, короткий) и refresh-токен.
- FR-3. Обновление access-токена по refresh-токену, выход (отзыв refresh).
- FR-4. Подтверждение email, сброс пароля **[later]**

### 4.2 Лекции
- FR-5. Создать лекцию: название, дата записи, источник.
- FR-6. Загрузить аудио одним файлом после окончания записи
  (типично 1,5 ч, ориентир до 500 МБ). Стриминг во время лекции **[later]**.
- FR-7. Загрузить фото доски, у каждого — таймкод (смещение в мс от начала записи).
- FR-8. Отправить лекцию на обработку (после загрузки аудио).
- FR-9. Список своих лекций и карточка лекции со статусом и прогрессом.
- FR-10. Получить готовый конспект (Markdown) и сырую расшифровку.
- FR-11. Удалить лекцию вместе с файлами.
- Пользователь видит и меняет только свои лекции.
- Редактирование конспекта в приложении не предусмотрено.

### 4.3 Обработка
- FR-12. Этапы: `TRANSCRIBING` → `READING_BOARD` → `GENERATING` → `ASSEMBLING`.
- FR-13. Прогресс: текущий этап + процент. Клиент опрашивает сервер;
  пуш через SSE **[later]**.
- FR-14. Ошибка этапа → один автоматический перезапуск с этого этапа.
  Повторная ошибка → статус `FAILED`, запись инцидента, уведомление команде
  в Telegram-бот.
- FR-15. Экспорт в PDF **[later]**.

### 4.4 Жизненный цикл лекции

```
CREATED ──(аудио загружено)──> UPLOADED ──(submit)──> QUEUED ──> PROCESSING ──> DONE
                                                                     │
                                                       ошибка ×1 → повтор этапа
                                                       ошибка ×2 → FAILED
```

## 5. Пайплайн ML

### MVP — вариант A (отдельные этапы)

1. **Распознавание речи**: whisper.cpp / faster-whisper → сегменты с таймкодами.
2. **Распознавание доски (OCR)**: pix2tex для формул, Tesseract для текста
   → текст и LaTeX для каждого фото.
3. **Генерация**: лекция режется на куски по 10–15 мин, к куску прикладываются
   фото с таймкодами в его интервале, локальная LLM (Ollama, Qwen2.5 7B–14B)
   пишет раздел конспекта.
4. **Сборка**: финальный проход — заголовки, оглавление, без повторов.

### Позже — вариант B **[later]**

Этап 2 заменяется vision-моделью (Qwen2.5-VL / Gemma 3), которая лучше читает
рукописные формулы. Благодаря отдельным этапам меняется только один воркер.

### Железо для разработки

- MacBook Air M4 — whisper.cpp на Metal.
- Ryzen AI 9 HX 370, 32 ГБ — LLM 7B–14B (квантованные) через Ollama/llama.cpp.

## 6. Взаимодействие оркестратора и воркера

- Exchange `smartlect` (direct); топологию объявляет оркестратор, воркер ждёт готовые очереди.
- Очередь задач на каждый этап: `lecture.transcribe`, `lecture.board`,
  `lecture.generate`, `lecture.assemble` — этапы разных лекций идут параллельно,
  воркеров каждого этапа можно добавлять.
- Очередь событий `lecture.events` (воркер → оркестратор): `PROGRESS`,
  `STAGE_COMPLETED`, `STAGE_FAILED`.
- Файлы через S3: в сообщениях передаются ключи объектов, а не сами данные.
- Воркер берёт по одной задаче (`prefetch=1`) и подтверждает её только после отправки
  `COMPLETED`/`FAILED` — при падении воркера задача вернётся в очередь.
- Задача публикуется в той же транзакции, что и смена статуса; события устаревшего этапа или
  попытки игнорируются, поэтому повторная доставка безопасна.
- Сообщения, которые не удалось обработать, уходят в `smartlect.dead`.
- `consumer_timeout` RabbitMQ поднят до 6 ч: распознавание длинной лекции на CPU дольше 30 мин.

## 7. API (черновик)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/register` | регистрация |
| POST | `/api/auth/login` | вход |
| POST | `/api/auth/refresh` | новый access-токен |
| POST | `/api/auth/logout` | выход |
| GET | `/api/me` | текущий пользователь |
| POST | `/api/lectures` | создать лекцию |
| GET | `/api/lectures?page=&size=` | список лекций (новые сверху, size ≤ 100) |
| GET | `/api/lectures/{id}` | карточка: статус, этап, прогресс |
| PUT | `/api/lectures/{id}/audio` | загрузить аудио (multipart) |
| POST | `/api/lectures/{id}/photos` | загрузить фото + `offsetMs` |
| GET | `/api/lectures/{id}/photos` | фото лекции по порядку таймкодов |
| GET | `/api/lectures/{id}/photos/{photoId}/content` | файл фото |
| DELETE | `/api/lectures/{id}/photos/{photoId}` | удалить фото (до отправки) |
| POST | `/api/lectures/{id}/submit` | отправить на обработку; для FAILED — перезапуск с упавшего этапа |
| GET | `/api/lectures/{id}/notes` | конспект (Markdown) |
| GET | `/api/lectures/{id}/transcript` | расшифровка |
| DELETE | `/api/lectures/{id}` | удалить |

## 8. Нефункциональные требования

- Работа локально через `docker compose`; позже — развёртывание на сервере.
- Пропускная способность масштабируется числом воркеров.
- Секреты не хранятся в коде для серверного развёртывания.
